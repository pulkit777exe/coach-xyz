# Frontend architecture & design audit — 2026-10-08

Three independent auditors, one per dimension, run the same way as the server audit: each
read the code and the written rules, and was **forbidden from reading the conclusions**
(`AGENTS.md`'s frontend section, `docs/`). Report below is consolidated; nothing was edited
by the auditors.

**What this is not:** independence. All three share my framing of what "architecture"
means here, so they looked for the classes I had already described. What they remove is my
memory of what I already checked.

## The correction that matters most

`scripts/webReachability.mjs` classifies six components as "loaded only by a generic render
sweep", and I had been writing that up as "rendered but proves markup, not values" for six
rounds. **That is wrong.** All six are `skip:` entries in `components/a11y-name-sweep.test.tsx`
— `runCase` returns `{status:'skipped'}` before importing anything, so the sweep observes
**zero bytes** of them. The gap is total, not partial.

And **two of the six skip reasons do not reproduce.** Measured by importing each module and
calling `renderToStaticMarkup` directly:

| component | recorded reason | actually |
|---|---|---|
| `StudentsClient.tsx` | "reads a store/context undefined until a client effect populates it" | **renders, 17,370 bytes.** It has no `useEffect`, no `useContext`, no `useRef` — only `useState`/`useMemo`. The reason names a mechanism the file does not have. |
| `SettingsPanel.tsx` | "a client-only child resolves to undefined in a server render" | **renders, 2,584 bytes.** No portal; `sections` is a prop; the only state is `activeId`. |
| `HeaderClient.tsx` | "usePreferences outside its provider" | half right — the provider is needed, but the first throw is actually `usePathname()` returning `null` at `:35` |
| `AuthHeader.tsx` | "renders directly" (inline comment contradicts its own `skip`) | accurate — it is async and suspends |

A `skip:` entry carries no `render` function, so **nothing in CI ever re-tests the claim.**
This is the repo's own "an exclusion is a coverage claim, and claims are not evidence"
lesson recurring inside the mechanism built to apply it.

## Recorded, not fixed — with locations

**`AuthHeader` is the highest blast radius and is in `app/layout.tsx:60`, so it decides the
chrome on every page.**
1. `:41-42` — `role` comes from the **account-level** row (`users.role`, `'coach'|'player'`)
   while every affordance it gates is **org-scoped**. A user whose account says `player` but
   who is `head_coach` in the club `resolveOrgContext` selected loses the org pill *and* the
   Dashboard link (`HeaderClient:287,312,317,327`). The two lines are adjacent, which is what
   lets this survive review — each looks right alone. **Which source is authoritative is a
   product decision, not an auditor's.**
2. `:33` + `:46` — a rejected `getOrgContext()` (no `.catch`) produces props **byte-identical**
   to the intended fresh-account fallback, so a Neon blip renders an "Owner" pill pointing at
   the wrong org.
3. No `<Suspense>` above it in `app/layout.tsx` — every route blocks first paint on an Auth0
   round-trip plus up to three fetches.

**`StudentsClient` — destructive bulk actions report success they did not have.**
- `:414-416` — `applyBulkStatus` counts rejections into `ok` (`:413`) then rewrites local state
  for **every** selected row regardless. Three selected, one 500s → the UI shows all three
  changed and toasts "Updated 2".
- `:432` — `confirmBulkDelete` drops `selected.has(p.id)` from the view wholesale, so an
  un-deleted row disappears from the UI. The smoke asserts server state, so only a DOM test
  sees the divergence.
- `:501-504` / `:965-968` — `onImported` calls `refreshStudents()` **bare**: no `await`, no
  `.catch`, promise discarded — while `toast.success('Roster updated')` has already fired. A
  silent fallback that is also wrong.
- `:132` — `hasHeader` is true if any cell matches an alias, and the alias list contains bare
  `'status'`, so a genuinely headerless CSV whose first data row contains that word is treated
  as a header and **silently loses its first player**.
- `:520-528` vs `:406-422` — single-archive removes the row from view, bulk-archive does not.
  Same file, opposite behaviour.

**Two more, small and certain.**
- `buildSettingsSections.tsx:341` — the Plan & usage nav entry exists only when `subscription`
  is non-null, so the left nav **reshuffles under the cursor after load**. The code is
  explicitly aware of this for Records (`:374-375`) and applied it there only.
- `HeaderClient.tsx:289-291` — the comment says "Marketing visitors never hit the API", but
  `usePreferenceSync(Boolean(user))` runs **before** the marketing branch, so a signed-in
  visitor to `/pricing` fires `GET /api/me/settings` and a debounced `PUT`.

**Guards that do not guard.**
- `lib/__tests__/typeScale.test.ts` reads only `app/globals.css` and `DESIGN_FOUNDATIONS.md`;
  it contains **zero** references to `.tsx`. AGENTS.md's "pinned by `typeScale.test.ts`" is
  unpinned where it matters.
- No guard exists for hex / `dark:` / palette classes: 34 `dark:` sites, two files of raw hex,
  held by convention. A real one needs an exemption list first — `components/9ui/**` and
  `components/interior/**` are vendored, and the hexes in `chart.tsx:55` are **CSS attribute
  selectors** matching Recharts' output, not colours. Stripping them would break the override.
- `SettingsPanel.tsx:133` depends on `[sections]`, an array prop its only caller rebuilds every
  render (`SettingsClient.tsx:85`), so the scroll-spy effect re-runs on every settings state
  update and can yank `activeId` to the last section.

## Not machine-verified

**Nothing on this list is left to a human eye, including the canvas.** Canvas *drawing*
cannot be asserted in jsdom, but the colour *decision* is three pure functions
(`themeColor`, `withAlpha`, `scoreColor`), so exporting them and testing them pins it.

And writing that test is what caught the gap it introduced: all thirteen helper cases
stayed green while the progress fill was reverted to iOS blue, because a correct helper
nobody calls is still a defect. **Proving a helper behaves correctly is not proving the draw
path uses it.** `VideoPlayer.colors.test.ts` therefore also carries a source-level tripwire
over the `fillStyle` assignments, and its first version was wrong in the other direction —
demanding zero literals, which could only have been satisfied by tokenizing the seven
overlay-chrome scrims drawn on top of video. Those must *not* follow the theme
(`--foreground` is near-black in light and near-white in dark, and neither reads against
unpredictable footage), so they are a named exemption whose members are asserted still
present. Seven mutations, all red.
