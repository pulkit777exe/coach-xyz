LIMITS, stated so this number is not over-read:
  * Reachability is a graph fact, not an execution fact. A reachable file
    may have none of its branches run — the render sweep proves markup,
    not values.
  * "Loaded only by a generic sweep" is the bucket that READS as covered and
    is not: the render sweep proves markup and accessible names, never a
    value. A component in that bucket has no test written for its behaviour.
  * That bucket is an UPPER BOUND, and measurably so: it is keyed on "some
    test calls readdirSync", not on "this file was enumerated". Mutating the
    sweep so it walks NOTHING leaves the numbers unchanged, because the
    detection cannot see it. It is right for this repo only because the
    sweep walks from the components directory itself, so enumerating means
    every component — revisit this line if the sweep's roots ever change.
  * Barrel imports make this an OVER-count in the covered direction — a file
    reached through `@/components` counts as reachable while its own code
    never executes. Same trap server/scripts/coverage.ts documents for Bun
    and its child-process probes.
  * Line counts are whole-file, so a 3-line helper weighs the same as a
    400-line component. Sorted by lines to make that visible, not to
    pretend it is a priority score.
